# 中文技术表达

## 何时使用

所有面向工程师的中文输出：面试题、审核意见、评分卡、总结。目标是让人一眼抓到结论，而不是显得专业。

## 三条硬规则

1. **结论先行**。每段第一句说结论，后面才是依据。不要"考虑到……综合来看……因此建议"。
2. **一句一个判断**。超过 40 字就拆。中文长句里的从句套从句，读者要回读。
3. **术语一致**。同一个概念全文只用一个词：别一会儿"接口"一会儿"API"一会儿"服务端点"。

## 术语对照

优先用工程师日常说的中文，首次出现可带英文：

| 用 | 不用 |
|---|---|
| 并发 | 并发度、并行数（混用时） |
| 超时 | 超时时间设置 |
| 幂等 | 幂等性保证能力 |
| 回滚 | 版本回退操作 |
| 兜底 | 保底方案 |

代码标识符、函数名、配置项一律保持原文，不翻译、不加书名号。

## 分级用词

严重度、优先级这类判断，用固定词表，不要自由发挥：

- 阻断级：**会导致**（数据丢失、服务不可用、越权访问）
- 需修：**在 X 条件下会**（高并发、异常输入、跨时区）
- 建议：**可以**（可读性、可维护性）
- 观察：**暂无影响，但**（技术债、依赖偏旧）

禁用"严重""非常""极大"这类程度副词代替判断——它们不提供信息。

## 代码块

- 给修复建议时贴**改后的代码**，不要只描述"应改为参数化查询"
- 代码块前一句话说明这段在干什么，代码块后不重复
- diff 片段带上文件与行号，方便定位

## 不要写

- 开场恭维（"这个问题很好"）
- 收尾套话（"希望对你有帮助""如需进一步了解请随时告知"）
- 营销词（赋能、闭环、抓手、颗粒度、组合拳）
- 反问式过渡（"那么问题来了"）
- 无信息量的免责（"具体情况具体分析"）——要么给出判断条件，要么不说

## 长度

能一句话说清就不写一段。面试题题干控制在 150 字内，单条审核意见控制在 120 字内（不含代码）。超了就是没想清楚。
