# 安全审查清单

## 何时使用

- 审核包含鉴权、上传、SQL / 命令拼接、外部请求、序列化的改动
- 判断一个安全问题该定"高"还是"中"
- 需要给出能直接照着改的修复建议

## 按改动类型查

### 输入进入执行路径

- SQL 拼接：字符串拼接 + 用户输入 → 注入。改参数化查询，不要用转义函数兜底
- 命令拼接：shell=True / Runtime.exec(字符串) → 命令注入。改参数数组
- 模板渲染：用户输入进模板源码而不是进上下文 → 模板注入
- 反序列化：pickle / Java 原生序列化 / yaml.load 读到外部数据 → 远程执行

### 鉴权与越权

- 接口有没有校验"这个资源属于当前用户"（横向越权最常见，IDOR）
- 权限判断写在路由层还是业务层：写在路由层时，内部调用绕过它
- 批量接口是否逐个对象校验，还是只校验了第一个
- 管理员接口是否只靠前端隐藏入口

### 凭证与配置

- 密钥、Token、连接串硬编码，或写进默认配置文件
- 错误信息把栈、SQL、内部地址返回给客户端
- 日志打印了身份证、手机号、完整 Token（应打码到保留前后各 4 位）
- 调试开关、测试后门、`skip_auth` 之类的开关被带进生产

### 出网与 SSRF

- 用户可控 URL 直接请求（webhook、图片抓取、代理）
- 没有限制内网段、回环地址、云元数据地址（169.254.169.254）
- 重定向后没有重新校验目标

### 依赖与供应链

- 新增依赖看：维护状态、最近一次发布、是否引入 postinstall 脚本
- 锁文件是否被顺手改动（可能夹带版本漂移）

## 严重度判定

| 等级 | 判定标准 | 例子 |
|---|---|---|
| 高 | 未授权即可利用，或直接拿到数据 / 执行代码 | 无鉴权的管理接口、SQL 注入、硬编码生产密钥 |
| 中 | 需要已登录身份，或需要特定条件触发 | 横向越权、日志泄露手机号、SSRF 未限制内网 |
| 低 | 纵深防御缺失，单点不可利用 | 错误信息过多、缺少速率限制、依赖版本偏旧 |

判定时只回答三个问题：**谁能触发、需要什么前提、最坏结果是什么**。不要用"感觉比较严重"下结论。

## 修复建议怎么写

一条建议必须包含：改哪个文件哪一行、改成什么、为什么这样就安全了。

```
差：这里存在 SQL 注入风险，建议修复。
好：user.py:42 的 f-string 拼接改为
    cursor.execute("SELECT * FROM users WHERE id = %s", (uid,))
    驱动会把 uid 当参数传输而不是拼进 SQL，注入面消失。
```

## 边界

- 只报**这个 diff 引入或加重**的问题；存量问题单独标注"存量"，不要混进本次结论
- 不确定可利用性时，写清"需要确认 X 才能定级"，不要直接标高
- 不把代码风格、命名、注释缺失算进安全清单
