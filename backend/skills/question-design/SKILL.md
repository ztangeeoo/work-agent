# 场景化出题

## 何时使用

- 出一套新题，需要避免"什么是 X"式的背诵题
- 已有题目太平，需要补上现场感和追问层次
- 候选人答得太顺，需要往下挖一层看边界

## 一道题的骨架

四段，缺一段就会变成背诵题：

1. **场景**：一句话交代系统在做什么、体量多大。带具体数字（QPS、数据量、团队规模），不要"某大型系统"。
2. **约束**：不能改什么。约束才是区分度所在——没有约束，任何方案都能自圆其说。
3. **现象**：可观测的异常。给监控指标、错误日志片段、时间线，而不是"出现了性能问题"。
4. **三问递进**：
   - 第一问定位（你怎么确认是这里）
   - 第二问归因（为什么会这样）
   - 第三问取舍（两种改法选哪个，代价是什么）

## 追问链

追问不要换题，要沿同一条因果链往下走：

```
现象 → 你的判断依据 → 如果这个依据不成立呢 → 极端流量下还成立吗 → 你怎么验证
```

每一层只增加一个变量。一次加两个变量，候选人会不知道你在问什么。

## 难度调节

| 想要的效果 | 调什么 |
|---|---|
| 更容易 | 把约束说全，把现象指到一个模块 |
| 更难 | 只给现象不给模块，加一条互相冲突的约束 |
| 看深度 | 追问"为什么不用 X"，让他自己否定一个方案 |
| 看广度 | 在同一场景里换一个维度（从一致性换到可观测性） |

## 反模式

- 题干里出现"请简述""请说明"——这是在考表达，不是在考判断
- 三个问题彼此独立——那是三道题，不是一道题
- 场景里的数字和问题无关——装饰性数字会让候选人分心
- 追问变成"再想想"——没有新信息的追问等于施压，不产生区分度
