0一页速查

五条铁律

  1. 颜色只从 token 取。业务代码里不出现 #hex、不出现 rgba(7,193,96,.1) 这种手拼值，一律 var(--md-*)。唯一例外是图表配置对象（见 §12 注）。
  2. 绿色分两条轨。色块、色条、图标、选中态用 --md-brand（#07C160）；凡是写字就用 --md-brand-text（#0E7C46）。微信绿当文字只有 2.38:1，是真实的可读性缺陷。
  3. 字号只用 6 档、字重只用 2 档。字号 12 / 14 / 16 / 20 / 24 / 28，字重 400 / 500。禁用 600 / 700 / bold。
  4. 间距只用 4 的倍数，优先 8 的倍数；圆角只用 7 档（§3）。
  5. 同一个状态在任何页面都是同一个颜色。业务状态先归到 5 个语义类，再由语义类决定颜色（§8）。颜色不表达「业务含义」，只表达「操作优先级」和「状态」。

1颜色 已落地

1.1 品牌双轨（微信绿）

微信绿足够「嫩」，但作为文字只有 2.38:1，不达 WCAG AA（正文要求 4.5:1）。所以主色拆成两条轨，各管一件事：

轨道变量用在哪白底对比度
填充轨--md-brand #07C160色条、选中态底、图标、进度条、图表主色、状态点2.38 : 1
文字轨--md-brand-text #0E7C46绿色文字、链接、plain 按钮文字、弱底上的强调文字5.26 : 1
实底轨--md-brand-solid #0E7C46实心主按钮、用户气泡（配 --md-on-brand 白字）5.26 : 1
浅色阶--md-brand-subtle #E6F9EFhover 底、选中行底、plain 底、弱强调块装饰性
实心按钮为什么不用 #07C160 白字压在 #07C160 上只有 2.38:1 —— 按钮文字是正文级字号（14px / 500），必须有 4.5:1。 所以「视觉上的品牌绿」和「能承载白字的绿」必须分开：实底按钮取 #0E7C46（5.26:1）， 品牌绿继续负责不需要写字的地方。这条比「主色统一」重要。

浅色阶不要自己拼 rgba(7,193,96,.1)：它是半透明混色，叠在不同底上颜色会变，且深色主题下方向是反的。

1.2 语义色四件套

每个语义色给四个值，一一对应「底色 / 描边 / 文字」三种用法。success 复用品牌轨 —— 全站只有一种绿。

语义主色（填充）浅底描边文字轨
success#07C160#E6F9EF#83E0B0#0E7C46
warning#E6A23C#FDF5E6#F5D3A8#B45309
danger#F56C6C#FDECEA#FBC4C4#DC2626
info#909399#F4F5F8#DCDFE6#6B7280
语义主色不能直接当文字色 warning #E6A23C 白底 2.19、danger #F56C6C 2.90、info #909399 3.08 —— 全部不达 AA。 主色只能做底色和图标，写字一律走对应的「文字轨」（--md-warning-text 等）。

1.3 中性色与表面阶梯

文字分 4 级，表面分 4 级。表面对比度决定「卡片看不看得出边界」：

Token值用途对比度
--md-text-1#303133标题、主要正文13.02 : 1
--md-text-2#606266正文、表格内容6.11 : 1
--md-text-3#6B7280辅助文字、说明、时间戳4.83 : 1
--md-text-4#A8ABB2禁用、占位符（非正文）2.30 : 1
--md-surface-0#EBEEF2页面底1.16 : 1（对白卡）
--md-surface-1#FFFFFF卡片、面板、输入框—
--md-surface-2#F5F7FA次级块、表头、hover 底装饰性
--md-border#DCDFE6可交互控件边框装饰性

页面底不要用「几乎和白色一样」的灰 #F5F7F9 与白卡只有 1.07:1，肉眼分辨不出边界，会被当成「灰底丢了」。 本规范取 #EBEEF2（1.16:1）。可调档位：#F2F4F7 1.10 / #EBEEF2 1.16 / #E8EBEF 1.20； 到 #E3E7EC（1.24:1）就显灰重，不要越过。

1.4 业务涨跌色（与品牌色隔离）

只在「增减 / 流入流出 / 评分升降」类场景启用。遵循国内习惯：正 = 红、负 = 绿；负值的绿取偏青的 #0E7490，避免与品牌绿混为一谈。

变量值用途对比度
--md-up#CF1322增长、正数、得分上升5.57 : 1
--md-down#0E7490下降、负数5.36 : 1
--md-flat#6B7280持平、零值4.83 : 1
与 danger / success 不是一回事 涨跌色表达方向，danger / success 表达状态。不要因为「负数」就用 danger 红，也不要因为「评分上升」就用 success 绿 —— 那会让「成功」和「上升」混为一谈。

1.5 题型分类色（本项目扩展）已定案

「一题一卡」的左侧色条与题型标签需要区分题型：基础 / 场景设计 / 深挖 / 算法 / 排查。这是分类色，不是语义色 —— 它不表达好坏，所以不能借用 success / danger。

题型主色（色条 / 徽标底 / 文字）浅底白字浅底上文字

每个值同时满足两种用法：作徽标底（白字 ≥ 4.5:1）与作浅底上的文字（≥ 4.5:1），所以「色条色 == 文字色」只需要一个变量。 新增题型只能从这张表里挑，不要临时调一个新色号 —— 一旦色相接近，两个题型就分不出来了。

2字体与字号 已落地

2.1 字体栈

拉丁字符走 Helvetica，中文回落苹方 / 雅黑。不要改成纯中文栈，那会让英文与数字变胖：

"Helvetica Neue", Helvetica, "PingFang SC", "Hiragino Sans GB",
"Microsoft YaHei", "微软雅黑", Arial, sans-serif   /* = --md-font-sans */

唯一例外是等宽场景 —— 哈希、流水号、报文、代码。定长字符才能目视核对：

.md-mono { font-family: var(--md-font-mono); }   /* Consolas, Monaco, "Courier New", monospace */

数字要竖向比对时再加 .md-num（font-variant-numeric: tabular-nums）—— 否则等宽数字不成立，右对齐也没用。

2.2 字号 6 档

存量里的 11 / 12.5 / 13 / 13.5 / 15 / 18 / 22 按就近原则归并：11→12、12.5/13/13.5→14、15→16、18→20、22→24、34/46→只用于纯图形（emoji / 插画），不用于文字。

归并时注意撑破固定宽度 13px → 14px 会让原本刚好放下的按钮、标签换行。这类位置先确认容器宽度是否 min-width 约束，再改字号。

2.3 字重只有 400 / 500

中文字体没有真正的 700，浏览器会做伪加粗：笔画粘连、观感粗糙，反而比 500 更糊。

场景字重说明
正文、气泡、表单400默认
标题、表头、强调500中文可用的最粗档
禁用600 / 700 / bold含 <b>、<strong>、内联 fontWeight
两个坑 ① <b> / <strong> 浏览器默认就是 700，token 文件里用 b, strong { font-weight: 500 } 兜底； ② 元素选择器压不过 class，内联 style={{ fontWeight: 700 }} 更压不过，这两类只能手改。

4按钮 已落地

4.1 只按「操作优先级」上色，三档

不按业务含义给按钮上色（新增用绿、导出用蓝、删除用红）。颜色表达优先级，这样它的含义才是稳定的：

优先级类名用于约束
主操作.btn-primary确认生成、保存并轮询一个区域最多一个
次操作.btn-ghost测试连接、取消、重置不加颜色
破坏性.btn.danger删除会话、清空对话二次确认

弹窗底部示例

取消 测试连接 保存并轮询

4.2 形态四层：色相 3 个，形态 4 种

plain 不是第四种颜色，而是同一色相的浅色档。这正是它叫「次色调」却不算新颜色的原因：

色相形态实际值用在哪
绿.btn-primary底 #0E7C46 + 白字 + hover #0A6B3A区域只有 1 个按钮时
绿plain（tag / chip 选中）底 subtle + 边 #83E0B0 + 字 #0E7C46主操作（有多个按钮时）
无彩色.btn-ghost底 #fff + 边 #DCDFE6 + 字 #606266次操作
红.btn.danger底 #FDECEA + 边 #FBC4C4 + 字 #DC2626破坏性操作
透明.b-link底透明、无边框行内操作、从属操作
对照：为什么「导出」不再是绿色按钮 主色改绿后，success 与 primary 是同一个绿，「新增」和「导出」会一模一样，反而分不清主次； 而且「导出」本身不是成功状态，用 success 语义就是错的。导出改为次操作 + 下载图标。

5表单 已定案

5.1 label 与结构

  • 标签与控件上下排布（对话式弹窗宽度有限，左右排会把控件压得很窄）。
  • label 字号 --md-fs-1 / 颜色 --md-text-3；控件内文字 --md-fs-2 / --md-text-1。
  • 两列栅格用 .row2（1fr 1fr + 10px 间隙），超过 2 列改为单列纵向。
  • 筛选项超过 6 个时分组，用 .section-title 分节，不要一屏铺 12 个输入框。

5.2 校验与错误提示

项规则
提示位置字段下方 .err-text，颜色 --md-danger-text，字号 12px。不要用 toast 弹校验错误
提交失败滚动定位到第一个错误字段，弹窗不关闭（配置丢失是最伤的体验）
文案「请输入模型 API 地址」「请选择代码平台」，不要出现字段英文名
成功提示绿色 .ok-text，只在有实质结果时出现；纯查询不弹「操作成功」

5.3 必填 / 禁用 / 只读

  • 必填在 label 后加 *，且颜色用 --md-danger-text（不要用主色绿，绿在这里不表意）。
  • 禁用 = 不可编辑且置灰（当前状态不允许改）；只读 = 纯文本展示（详情查看）。两者不要混用。
  • 只读详情不要复用编辑表单 + disabled，改成描述列表（键值对）更清晰。

6.2 一题一卡

6.4 代码块

  • 复制按钮必须有，且复制成功后按钮文案变化 1.5s 再还原。

7数据格式 已定案

本产品的核心是「评分」和「风险结论」，格式不统一时用户无法快速比对。本节优先级高于任何视觉细节。

7.1 数值

项规则示例

8.1 映射原则

业务状态值不能直接决定颜色，先归到 5 个语义类，再由语义类决定颜色。这样同一个状态在任何位置都是同一个颜色。

13.2 切换入口

右上角齿轮左侧有一个圆形图标按钮（.cfg-btn.theme-btn），浅色下显示月亮、深色下显示太阳 —— 图标表达「点下去会变成什么」，不是当前状态。偏好存 localStorage.theme。

文件职责
web/src/lib/theme.ts唯一入口：loadTheme / applyTheme / saveTheme / initTheme
web/src/main.tsx渲染前调 initTheme()，让 React 状态与已挂的类对齐
web/index.html内联脚本，样式加载前就挂类 —— 防首屏闪白
web/src/ChatApp.tsx按钮 + useState，变更时 applyTheme + saveTheme
 
const [theme, setTheme] = useState<Theme>(loadTheme);
useEffect(() => { applyTheme(theme); saveTheme(theme); }, [theme]);
防闪白必须是内联脚本，不能只靠 React main.tsx 是 type="module"（延迟执行），浏览器可能已经先画了一帧白底。 所以 index.html 的 <head> 里要放一段普通 <script>，在样式生效前就把 dark 类挂上。
踩过的坑：类必须挂在 <html> 上 :root 里的映射变量（--bg: var(--md-surface-0)）在声明处就完成了替换。 只在某个后代 div 上覆盖基础 token，不会让映射变量重算 —— 结果是「类加上了、颜色一个没变」。

首次访问默认浅色，不跟随系统偏好。首屏观感被系统设置突然改掉属于意外行为；要支持「跟随系统」应当做成三档显式选择（浅 / 深 / 跟随），而不是默认行为。

13.3 自检清单

  • 两种主题各走一遍：文字在各自底色上是否可读；绿色是否走了文字轨。
  • 容易漏的浮层：弹窗、下拉、toast、遮罩、空状态、骨架。
  • 代码块：应当保持不变（深色），不是「也跟着变亮」。
  • 分类徽标：底色变亮后，白字要翻成深字（--md-on-cat）。
  • 新增颜色时两种主题都要看，别只在亮色下调。

14.2 兼容别名层

styles.css 顶部的 :root 保留了旧变量名（--bg / --panel / --primary …）， 它们都写成 var(--md-*) 的引用而不是取值，所以切暗色时会自动跟随。新代码不要再使用这一层。

已下线的旧语义 --primary-dark 原本是「深一点的蓝」，改绿后语义变成「绿色文字轨」。 如果看到它被当作背景色使用，那是 bug —— 背景应该用 --md-brand-solid。

14.3 禁止事项

  • 不要再在业务代码里写 #hex。包括内联 style={{ background: '#4f6ef7' }} —— 这种写法最容易被漏掉，因为 grep 只搜 css 文件时看不见。
  • 不要改 --md-fs-* 的比例关系。行高与字号是成对定义的，单独改字号会得到拥挤或松散的段落。
  • 不要用状态切换内联样式。需要两个颜色的状态，写成两个类名（.pr-dot.is-running），不要 style={running ? 'red' : 'gray'}。
  • 不要一次性全量改写业务组件。按模块分批、每批单独提交，便于回滚与目视核对。
